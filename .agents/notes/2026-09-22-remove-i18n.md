# 决策: 移除 i18n，文案就地写并统一英文

状态: 已实施

## 问题

i18n 迁移（每条消息一条目录项、`DSHCTL_LANG` 选择语言）完成后，维护代价被判定为不值：

- 一条消息有两个家（调用点的参数与 `messages.go` 里的 `Message`），改一句话要同时改
  两处，漏改一处只有测试能发现；目录还会出现"没人渲染的孤儿"。
- 调用点从"直接说出这句话"退化成"引用一个 id"，读代码要跳一次才能知道终端上会打印
  什么；错误路径尤其如此。
- 本产品的操作者是同一批人（中文母语、读英文技术输出），双语目录买到的东西（界面语言
  可切换）在实际使用中没有人要，代价却摊在每一句话上。

## 决定

- 删掉 `internal/i18n`（语言解析、`Catalog`/`Message` 类型、`Merge`、`Audit`）、各包的
  `messages.go` 与 `DSHCTL_LANG`。
- 每一条面向操作者的文案还原到产生它的调用点，并且统一写成英文：错误、帮助、状态、
  体检、日志、测试失败信息。
- 其余设计（垂直分层、事件端口、金标与账本、机制/资源划分）不变。

## 备选方案

- **保留目录、只留英文**：仍然是一条消息两个家，只是少了一半翻译，没有解决维护问题。
- **保留 i18n 但按需迁移**：迁移一半会留下两套写法，读代码的人要先判断这条消息在哪。
- **继续双语**：见"问题"。
- **保留语言层但去掉目录**（运行时按语言选模板）：仍然要在代码里维护两套句子，
  而且把"这句话说什么"和"用哪种语言说"重新耦合起来。

## 后果

- 文案只有英文。README（对外契约、中文）与代码里的英文文案各司其职：README 描述行为，
  代码说出运行时的那句话。
- 金标（`internal/conformance/testdata/expected-*.json`）记录英文输出；归一化规则里针对
  中文的 `耗时 \S+` 改为 `took \S+`。
- `scripts/check-conventions.py` 不再有 `i18n-literals` 规则，也不再有指向
  `internal/i18n` 的依赖边；`LAYERS` 只登记真实存在的包。
- 决策名册与账本里与 i18n 有关的两条锚点、九行账本、两条决策随包一起移除；`make
  mutation` 的 `--audit` 与账本 `--strict` 仍然全绿。
- 迁移中踩到两个坑，记在这里备查：按"常量名"解析 id 时多个包的同名常量会串文案
  （`MsgReadFailed`、`MsgNotRegularFile`…，共修正 4 处）；把消息插进 Go 字符串字面量
  必须先解码再重编码，否则 `\n` 会被二次转义，`+"\n"` 这类拼接也不能被整段替换吞掉。

## 验证

- `go test ./internal/... ./cmd/... -count=1` 全绿。
- `make fmt-check conventions vet` 通过；`conventions` 的包图里不再有 `internal/i18n`。
- `go test ./internal/conformance/ -update -count=1` 重新录制本平台金标后，
  不带 `-update` 的运行逐字节通过（其余平台的金标由 CI 的 `goldens` 作业录制）。
- `python3 scripts/mutation-check.py --audit` 全部锚点唯一匹配；
  `python3 scripts/accounting/check-accounting.py --strict`（经 `make conventions`）通过。
