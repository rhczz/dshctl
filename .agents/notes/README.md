# 决策记录

这里存一类东西：**为什么这么做，以及放弃了什么**。它是代码、README、测试都装不下的部分——被否决的方案、代价、将来可能被重新提起的判断。当前状态去 README 和包文档，被钉住的行为去测试，操作步骤去 skill。

## 何时写一条

改变行为、契约、磁盘或配置格式、流程，或做了一次"该固定还是该可配"的判断时，必须与代码同一提交写一条。纯机械或本机改动豁免。已经有记录拥有这个决定时更新那一条，不要新建重复的。

## 命名与格式

文件名 `yyyy-mm-dd-kebab-case.md`，日期是第一次提出这个决定的日期。正文骨架见 [`_template.md`](_template.md)，由 `scripts/check-conventions.py` 校验：

- 第一行 `# 决策: <标题>`；
- `状态: 已实施` 或 `状态: 已否决 — <一行原因>`，没有第三种；
- `## 问题` 说清楚动机，不依赖后面的方案也能读懂；
- `## 决定` 用现在时描述已经成立的事实；
- `## 备选方案` **必写**：每个真实考虑过的方案和它落选的原因，一条一段。没有记录它击败了什么的决定，会不断被重新讨论；
- `## 后果` 写这次取舍付出了什么、换来了什么；
- `## 验证` 写今天靠什么证明这个决定仍然成立（测试、门禁命令、探针）。

备选方案是记录下来的，不是事后编的。一个决定被后来的记录取代时，新建一条并与旧的互链，不要把旧记录改写成另一个决定。

## 与其他层的关系

一个事实只有一个家：操作者需要知道的结论在 `README.md`，代码级的模型与不变量在包文档，被钉住的行为在测试，这里的只有理由与被放弃的路径。
