# 决策: 面向操作者的每一句话都是一条目录项

状态: 已实施

> 取代：2026-09-22-remove-i18n.md —— 该决定随后被移除，文案改为就地写英文。

## 问题

提示文案写死为中文，散布在 cli/app/基础设施约 200 处。操作者要求中英双语、默认英文、
按机器语言选择，且这个能力要能长期扩展（新语言、新文案）。写死字符串的后果是：
一条消息的语言由它所在的文件决定，翻译是全文替换而不是加一段文本。

## 决定

1. **目录在 `internal/i18n`**：`Messages` 是一条条 `Message{EN, ZH}`，用**常量 id** 引用
   （`i18n.T(i18n.MsgStateRunning)`）。拼错 id 是编译错误；未知 id 渲染成 id 本身
   （在输出与金标里一眼可见，而不是空行）。
2. **完整性是类型**：一条消息一个语言字段。新增语言 = 加一个字段，编译器会把所有漏填的
   消息指出来；`TestCatalogIsComplete` 再钉住两种语言都非空，`TestNoOrphanMessages`
   拒绝没人渲染的目录项。
3. **语言解析只有一处**：`DSHCTL_LANG` > `LC_ALL` > `LC_MESSAGES` > `LANG`，认不出的
   语言按英文处理（不做半翻译）；解析在 `cli.Main` 发生，`i18n.Use` 安装，
   单条消息缺译文时回退英文。
4. **语言不穿参数**：不为语言给每个函数加参数；需要确定语言的测试显式安装翻译器。
5. **金标钉住 `DSHCTL_LANG=zh`**：conformance 的金标录自 v0.2.5（中文），
   显式钉语言让差分预言机继续"比行为"而不是"比机器语言偏好"。

## 备选方案

- **运行时加载 JSON/YAML 语言包**（`go:embed`）：灵活，但把"漏翻译"从编译期错误变成
  运行期缺口，且引入文件格式与校验；本项目的文案量不需要。
- **每条消息一个函数**（`func MsgX(args...) string`）：同样类型安全，但目录变成几十个
  函数、审计完整性要遍历代码。
- **按包各建一份目录**：分散了"操作者能读到什么"的清单，孤儿消息难以发现。
- **把翻译器穿进每个签名**：会污染与本问题无关的参数列表，且 `domain` 会被迫依赖 i18n。
- **只做中文、加一个 `--lang`**：与"默认英文"的要求相反。

## 后果

- `internal/i18n` 是零依赖叶子，任何层都可以渲染消息；`domain` 不再放文案
  （`Status.Summary` 移到服务层 并走目录）。
- 迁移是逐步的：新代码必须走目录，旧文件被改动时顺手迁移；`dshctl-style` 与
  `dshctl-review` 已把这条写成规则。
- `DSHCTL_LANG` 成为对外契约（README、`documentation_test`、`readme-env` 检查同步）。

## 验证

- `internal/i18n/i18n_test.go`：解析顺序与回退、两种语言渲染、缺译文回退、未知 id、
  目录完整性、孤儿消息。
- `internal/conformance`：`DSHCTL_LANG=zh` 下与 v0.2.5 金标逐字节一致；
  `go run ./cmd/dshctl status` 在 `DSHCTL_LANG` 缺省/`zh`/`en`/`fr` 下分别输出英文/中文/英文/英文。
